## Детализированный план по главам и параграфам

### Введение
* **Актуальность темы:** переход к микросервисным распределённым системам, предел эффективности классических статических эвристик (HPA, Round-Robin, статические алерты), рост сложности расследования инцидентов (MTTR).
* **Степень разработанности темы:** концепция AIOps, современные подходы к интеллектуализации мониторинга и управления (Dynatrace, Datadog, Keptn, KEDA).
* **Объект исследования:** процессы мониторинга, маршрутизации и масштабирования в распределённой микросервисной инфраструктуре.
* **Предмет исследования:** алгоритмы машинного обучения, методы анализа временных рядов и архитектуры RAG на базе LLM для проактивного управления жизненным циклом микросервисов.
* **Цель работы:** проектирование и программная реализация прототипа интеллектуальной платформы (CORTEX), обеспечивающей снижение задержек (latency), сокращение времени реакции на всплески нагрузки и ускорение диагностики инцидентов.
* **Задачи исследования:**
  1. Исследовать существующие методы и программные средства управления микросервисами и AIOps.
  2. Спроектировать распределённую модульную архитектуру платформы CORTEX и протоколы взаимодействия.
  3. Разработать программный модуль динамической ML-маршрутизации трафика на уровне API-шлюза.
  4. Разработать алгоритм и модуль предиктивного масштабирования подов в Kubernetes.
  5. Реализовать RAG-подсистему семантического поиска и анализа инцидентов по распределённым логам и трейсам.
  6. Спроектировать модуль LLM-агентов с механизмом безопасного выполнения операций (Guardrails).
  7. Развернуть экспериментальный полигон и провести сравнительные нагрузочные испытания.
* **Научная новизна и практическая значимость:** архитектура гибридного контура управления (сочетание классического Fallback и ML/LLM-агентов), открытый программный комплекс.
* **Положения, выносимые на защиту.**

### Глава 1. Аналитический обзор предметной области и существующих решений
* **1.1. Проблемы эксплуатации и масштабирования современных микросервисных архитектур**
  * Специфика распределённых систем: гетерогенность инстансов, каскадные сбои, сетевой оверхед.
  * Ограничения реактивных подходов (классический HPA на CPU/Memory, задержки инициализации контейнеров).
* **1.2. Концепция AIOps и платформенной инженерии**
  * Определение AIOps (Gartner) и уровни зрелости систем автоматизации.
  * Обзор существующих решений (Dynatrace Davis AI, Datadog Watchdog, open-source проекты Keptn, KEDA).
  * Сравнительный анализ существующих систем и выявление пробелов (отсутствие комплексных open-source решений с локальным LLM-контуром).
* **1.3. Методы динамической балансировки и маршрутизации сетевого трафика**
  * Алгоритмы Round-Robin, Least Connections, Weighted Response Time.
  * Применение моделей классификации/регрессии для предсказания деградации инстансов.
* **1.4. Модели и алгоритмы прогнозирования временных рядов в задачах автоскейлинга**
  * Статистические модели (ARIMA, SARIMA) vs нейросетевые (LSTM, N-BEATS, градиентный бустинг).
  * Особенности сбора телеметрии для прогнозирования нагрузки.
* **1.5. Технологии RAG и большие языковые модели в задачах анализа телеметрии**
  * Проблема анализа распределённых неструктурированных логов и распределённого контекста (OpenTelemetry/Jaeger).
  * Векторные базы данных и семантический поиск по логам при Root Cause Analysis (RCA).
  * Использование агентных LLM-паттернов (ReAct, Plan-and-Solve) в DevOps и проблемы безопасности (Guardrails).
* **1.6. Выводы по главе 1 и постановка частных задач разработки**

### Глава 2. Проектирование архитектуры интеллектуальной платформы CORTEX
* **2.1. Концепция и функциональные требования к платформе**
  * Сценарии использования (Use Cases) для разработчиков и SRE/DevOps.
  * Требования к отказоустойчивости (Fault Tolerance, Circuit Breaker) и Fallback-механизмам.
* **2.2. Архитектура системы (C4 Model)**
  * Context Diagram (внешние потребители, целевой K8s-кластер, LLM-провайдеры).
  * Container Diagram (API Gateway, Event Bus Kafka, Predictor Service, RAG Service, LLM Agent Service, Telemetry Collector).
  * Component Diagram ключевых микросервисов.
* **2.3. Проектирование модуля интеллектуального API-шлюза**
  * Архитектура перехвата запросов (Spring Cloud Gateway Filters).
  * Механизм скоринга инстансов и интеграция с ML-моделью.
  * Механизм Fallback (мгновенный откат на Round-Robin при недоступности AI).
* **2.4. Проектирование модуля предиктивного автоскейлинга**
  * Схема конвейера сбора метрик (Prometheus -> Kafka -> Predictor).
  * Протокол взаимодействия с Kubernetes API (Custom Metrics API / KEDA).
* **2.5. Архитектура RAG-подсистемы и векторного индекса телеметрии**
  * Пайплайн инжекции: парсинг логов/трейсов, эмбеддинги, индексация в Qdrant.
  * Пайплайн извлечения и генерации: контекстный промптинг, связывание трейса с ошибкой.
* **2.6. Архитектура LLM-агентов и модуль безопасного исполнения (Guardrails)**
  * Ограничения доступа (read-only операции vs подтверждаемые действия).
  * Валидация вывода модели и предотвращение галлюцинаций.
* **2.7. Стек технологий и обоснование выбора компонентов**
  * Обоснование связки Java 21/Kotlin + Spring Boot 3 для ядра.
  * Обоснование Python sidecar / LangChain4j / Qdrant / Ollama.
* **2.8. Выводы по главе 2**

### Глава 4. Экспериментальные исследования и оценка эффективности
* **4.1. Методика проведения экспериментов и стенд тестирования**
  * Описание синтетического микросервисного приложения-стенда.
  * Сценарии нагрузочного тестирования (k6): нормальная нагрузка, пиковые скачки (spikes), стресс-тесты.
  * Сценарии сбоев (Chaos Engineering): искусственные задержки сети, отказ подов, утечки ресурсов.
* **4.2. Исследование эффективности интеллектуальной маршрутизации**
  * Сравнение задержек (p50, p95, p99 latency) CORTEX vs Round-Robin при деградации отдельных инстансов.
  * Оценка пропускной способности (RPS) и процента успешных ответов (HTTP 200 vs 5xx).
* **4.3. Исследование эффективности предиктивного автоскейлинга**
  * Сравнение времени реакции на всплеск нагрузки: CORTEX vs стандартный Kubernetes HPA.
  * Анализ недовыделения (under-provisioning) и перерасхода (over-provisioning) ресурсов.
* **4.4. Оценка быстродействия и точности RAG-подсистемы (Root Cause Analysis)**
  * Замер среднего времени локализации первопричины инцидента (MTTR) оператором с RAG vs ручной поиск по логам.
  * Оценка релевантности и полноты ответов LLM (RAG Triad metrics: Context Relevance, Groundedness, Answer Relevance).
* **4.5. Анализ накладных расходов платформы и надежности механизма Fallback**
  * Дополнительное потребление CPU/RAM модулями CORTEX.
  * Скорость переключения на классические алгоритмы при падении ML/LLM компонентов.
